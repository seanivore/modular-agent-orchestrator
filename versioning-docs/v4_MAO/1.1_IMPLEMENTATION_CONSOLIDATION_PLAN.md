## **Mao v4 Philosophy: Full Interactive Application**

### **Architectural Distinction from SFA Legacy**
Mao v4 represents a **fundamental paradigm shift** from the previous SFA approach:

**SFA Legacy Approach:**
- Passive monitoring and ticker-style interface
- Minimal user interaction during execution
- Terminal-only, single-purpose tool

**Mao v4 Approach:**
- **Complete interactive application experience**
- Rich UI/UX with chat, menus, settings, live monitoring
- **UI portability architecture** - designed to translate seamlessly across platforms
- Professional interface quality rivaling Claude Code
- Terminal-first but architected for web, mobile, desktop expansion

This distinction affects every domain implementation - we're building a **comprehensive application platform**, not a monitoring utility.

## **Cross-Cutting Infrastructure: Modular CLI Architecture**

```bash
mao mao   # Start the application (Mao like a cat; you'll never forget)
```

### **JSON-Based Command System**
Mao uses a revolutionary approach where all CLI commands are defined in JSON configuration rather than hardcoded in Python:

```json
{
  "stats": {
    "type": "flag",
    "terminal_flag": "--stats", 
    "app_command": "/stats",
    "help": "Show system performance and orchestrator statistics",
    "interface_method": "stats"
  }
}
```

### **Dynamic Parser Generation**
- Runtime parser creation from JSON configuration
- Both terminal (`mao --stats`) and in-app (`/stats`) variants
- Easy command addition without code changes
- Comprehensive help system integration

### **Command Categories**
- **Standalone**: `mao --stats`, `mao --workflows`
- **Needs Input**: `mao --goal "create marketing plan"`
- **Needs File**: `mao --setup ./config.json` 
- **In-App Only**: `/restart`, `/exit`, 
- **Execute Bash/Zsh Commands from In-App**: `! restart`, `! exit`, `! ls -la`, `! cd /Development/Mao/`

### **Integration Points**
- Entry point routing through `mao_v4.py`
- Interface method dispatch in Terminal UI/UX System
- Setup script execution via Workflow Engine Core
- Command registration using MCP Integration Hub workflow IDs
