# 2.4 It's All Variable: The Philosophy in Action

## Where It All Started

The variable-input concept wasn't just a feature—it was the **philosophical breakthrough** that made everything else possible.

*[Content to be pulled from SFA README technical docs and use-case examples]*

In the early days, we had a simple but powerful realization: **the same agent architecture could handle completely different use cases just by changing the input variables**.

Instead of building separate agents for job applications, content creation, research, and analysis, we could build **one flexible system** that adapted based on configuration.

## The Original Variable-Input Architecture

*[Reference to SFA README "Variable-Input Architecture" and "Configuration Variables Explained" sections]*

The concept was elegant in its simplicity:

```json
{
    "use_case": "job_application",
    "target_role": "Senior Designer", 
    "company": "TechCorp",
    "focus_areas": ["portfolio", "experience", "cultural_fit"],
    "output_format": "cover_letter_and_resume"
}
```

vs.

```json
{
    "use_case": "content_strategy",
    "target_audience": "B2B SaaS",
    "content_types": ["blog", "social", "email"],
    "focus_areas": ["thought_leadership", "lead_generation"],
    "output_format": "editorial_calendar"
}
```

**Same agent. Completely different outcomes. All through variables.**

## The Philosophy Spreads

What started as a practical solution became an **architectural obsession**. If variable inputs worked for use cases, why not apply the same principle everywhere?

### Agent Files: Empty Templates

*[Reference to configs/ directory structure]*

Mao's agent files are intentionally generic—empty templates that get populated by configuration:

```python
# This is what an Mao agent looks like before configuration
class GenericAgent:
    def __init__(self, config):
        self.role = config.get('role')
        self.expertise = config.get('expertise') 
        self.tools = config.get('available_tools')
        self.behavior = config.get('behavior_patterns')
        self.goals = config.get('objectives')
```

**No hardcoded assumptions. No built-in limitations. Pure adaptability.**

### Models: Interchangeable Components

*[Reference to configs/models/ directory]*

Every AI model becomes a plug-and-play component:

```json
// configs/models/claude-sonnet-4.json
{
    "name": "claude-sonnet-4",
    "provider": "anthropic-direct",
    "capabilities": ["reasoning", "analysis", "creative_writing"],
    "cost_per_token": 0.000015,
    "context_window": 200000,
    "strengths": ["complex_reasoning", "code_analysis"],
    "optimal_for": ["strategic_planning", "technical_writing"]
}
```

```json
// configs/models/gpt-4.1-mini.json  
{
    "name": "gpt-4.1-mini",
    "provider": "openai-direct", 
    "capabilities": ["general_purpose", "fast_response"],
    "cost_per_token": 0.000001,
    "context_window": 128000,
    "strengths": ["speed", "cost_efficiency"],
    "optimal_for": ["quick_tasks", "high_volume_processing"]
}
```

Mao selects the optimal model for each task based on requirements, not arbitrary preferences.

### Tools: Universal Interfaces

*[Reference to tools/ directory 4-file pattern]*

Every tool follows the same interface pattern, making them completely interchangeable:

```json
{
    "name": "research_tool",
    "inputs": {"query": "string", "depth": "enum"},
    "outputs": {"results": "array", "summary": "string"},
    "interface": "standard_tool_v1"
}
```

Whether it's web search, academic research, or market analysis—the interface remains consistent.

### Providers: Abstracted Connections

*[Reference to configs/providers/ directory]*

Even API connections are variable:

```json
// configs/providers/anthropic-direct.json
{
    "name": "anthropic-direct",
    "type": "api_direct",
    "base_url": "https://api.anthropic.com",
    "auth_method": "api_key",
    "rate_limits": {"requests_per_minute": 60},
    "supported_models": ["claude-3-5-sonnet", "claude-3-opus"]
}
```

```json
// configs/providers/litellm.json
{
    "name": "litellm", 
    "type": "proxy",
    "base_url": "http://localhost:4000",
    "auth_method": "none",
    "rate_limits": {"requests_per_minute": 1000},
    "supported_models": ["*"]
}
```

Switch providers without changing a single line of core code.

## The "Do It Yourself" Philosophy

*[Reference to technical docs and use-case examples]*

This variable approach means you're never locked into our assumptions about how things should work:

### Custom Use Cases
Don't like our predefined workflows? Create your own:

```json
{
    "use_case": "podcast_production",
    "workflow": "custom",
    "phases": [
        {"research_topics": {"tools": ["web_search", "perplexity"], "depth": "comprehensive"}},
        {"script_writing": {"tools": ["text_editor", "think"], "style": "conversational"}},
        {"audio_production": {"tools": ["custom_audio_tool"], "format": "mp3_stereo"}}
    ]
}
```

### Industry-Specific Configurations
Tailor Mao for your specific domain:

```json
{
    "industry": "legal_services",
    "compliance_requirements": ["attorney_client_privilege", "data_retention"],
    "specialized_tools": ["legal_research", "document_review", "case_analysis"],
    "output_formats": ["legal_brief", "contract_analysis", "compliance_report"]

```

### Personal Preferences
Make Mao work the way you think:

```json
{
    "communication_preferences": {
        "verbosity": "concise",
        "technical_detail": "high", 
        "confirmation_requests": "minimal",
        "progress_updates": "milestone_only"
    }

```

## Why This Matters

The variable-input philosophy isn't just about flexibility—it's about **future-proofing**:

### No Obsolescence
When new models, tools, or techniques emerge, you don't need a new system—just new configuration files.

### No Vendor Lock-in
Your workflows and data aren't tied to specific providers or technologies.

### No Artificial Limitations
The system adapts to your needs rather than forcing you to adapt to its constraints.

### No Breaking Changes
Updates add capabilities without changing existing functionality.

## Everything is Variable, Nothing is Hardcoded

This philosophy permeates every aspect of Mao:

- **Agent behavior** is configured, not programmed
- **Tool selection** is dynamic, not fixed
- **Model choice** is optimized, not predetermined  
- **Workflow structure** is composed, not scripted
- **Resource allocation** is adaptive, not static
- **Success criteria** are defined, not assumed


## The Modular Promise Delivered

This variable architecture is what makes Mao's modularity more than just good organization—it's **practical magic**:

- Add new models without touching core code
- Create custom workflows without programming
- Integrate new tools without system changes  
- Adapt to new requirements without rebuilding
