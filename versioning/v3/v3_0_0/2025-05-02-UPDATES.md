1. **File Path Issue**: The token_stats.json file is being saved in the current working directory without a specific path, which means it could be saved in different locations depending on where the script is run from.

2. **Missing Workflow-specific Identification**: The token stats don't include any identifier for which workflow they belong to, so if multiple workflows are run, they might interfere with each other's stats.

3. **Initialization Logic**: The token counter is initialized at the module level, before any specific workflow is loaded.

Let's implement a more robust solution:

The changes I've made to fix the token tracking system include:

1. **Workflow-Specific Token Stats**:
   - Each workflow now has its own unique token stats file named `token_stats_{workflow_id}.json`
   - The stats file is stored in the same directory as the workflow config file
   - This prevents different workflows from overwriting each other's stats

2. **Proper Initialization**:
   - Added a `set_workflow_info()` method that's called at the start of each workflow
   - This method correctly identifies the workflow and sets up paths before loading stats
   - We now explicitly call this method at the beginning of the `main()` function

3. **Improved Error Handling and Logging**:
   - Better error messages if token stats can't be saved
   - Added more detailed logging about where stats are being saved
   - Formatted numbers with commas for better readability

4. **Fixed Phase Display Logic**:
   - Simplified the logic for displaying the current phase number
   - Directly checks if `phases` exists and uses its length for the denominator

These changes should resolve the persistent issues with token tracking. Now each workflow will:
1. Have its own dedicated stats file
2. Properly accumulate tokens across phases
3. Display accurate cumulative costs
4. Show token information in a more readable format

The key improvement is that we're now using the config file path to create a unique identifier for each workflow and storing the stats in the same directory as the config file. This ensures that token stats are properly associated with the specific workflow being run.
